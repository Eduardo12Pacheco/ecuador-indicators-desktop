# Lakehouse manifest v1

Ecuador Indicators can import a snapshot from a sibling lakehouse that stores
its data in DuckDB. The integration is optional and Python-only: the desktop
runtime never links DuckDB. The contract is a JSON manifest that describes the
DuckDB file and maps its relations and columns onto the schema-v1 snapshot
tables. The machine-readable definition is
[`pipeline/schemas/lakehouse-manifest.v1.schema.json`](../pipeline/schemas/lakehouse-manifest.v1.schema.json)
(JSON Schema draft 2020-12); ADR 0009 records why the contract is shaped this
way.

This is a proposed contract: no sibling lakehouse artifact existed to align with
when it was written.

## Command

```bash
cd pipeline
uv sync --extra lakehouse
uv run ecuador-data import-lakehouse \
  --manifest ../sibling-lakehouse/manifest.json \
  --out ../data/snapshot/from-lakehouse.sqlite
```

The output is a normal schema-v1 snapshot that the desktop application can open
through **Settings → Dataset → Open snapshot**. `import-lakehouse` does not
modify `data/MANIFEST.json`; it writes only the requested output file.

## Fields

| Field | Rules |
|---|---|
| `manifest_version` | `1.<minor>`, both parts numeric. A different major version is rejected. |
| `kind` | Must be `ecuador-indicators-lakehouse-export`. |
| `generated_at` | ISO-8601 timestamp with a UTC offset; becomes the snapshot's `source_last_updated` and `retrieved_at`. |
| `dataset.id`, `dataset.version`, `dataset.title` | Non-empty strings copied to `meta.dataset_id`, `meta.dataset_version` and `meta.source_name`. |
| `license.spdx`, `license.url` | Copied to `meta.license` and `meta.license_url`. |
| `license.attribution_en`, `license.attribution_es` | Non-empty; copied verbatim to `meta.attribution_en` and `meta.attribution_es`. |
| `duckdb.path` | Relative to the manifest directory; absolute paths and `..` segments are rejected. |
| `duckdb.sha256` | Lowercase hex SHA-256 of the DuckDB file bytes. |
| `relations.<table>.relation` | `table` or `schema.table`; each part matches `^[A-Za-z_][A-Za-z0-9_]*$`. |
| `relations.<table>.columns` | Exact mapping from every snapshot column of that table to a physical DuckDB column. Missing or extra keys are rejected; each physical name matches `^[A-Za-z_][A-Za-z0-9_]*$`. |

The snapshot tables and their columns are the schema-v1 tables documented in
[`docs/DATA.md`](DATA.md): `topic`, `geography`, `indicator` and `observation`
(`meta` is generated by the pipeline, not imported).

## Validation and errors

The manifest is parsed and validated before the DuckDB file is opened. DuckDB is
opened `read_only=True`; relations are read with the mapped columns and ordered
by their primary keys. Referential integrity is checked before writing:
indicators must reference a known topic, observations must reference a known
indicator and geography, and duplicate observation keys are rejected.

All contract and data failures exit `2` and print a message naming the file,
relation or column. Unexpected failures exit `1`.

| Condition | Message (abridged) |
|---|---|
| Manifest missing, unreadable or invalid JSON | `lakehouse manifest not found: manifest.json` / `... is not valid JSON` |
| Unsupported major version | `invalid lakehouse manifest: ... manifest_version major must be 1` |
| Wrong `kind` | `invalid lakehouse manifest: ... kind` |
| Missing or extra column mapping | `invalid lakehouse manifest: ... missing column mapping for observations: year` |
| Unsafe relation or column identifier | `invalid lakehouse manifest: ... unsafe column identifier` |
| DuckDB path absolute or escaping | `lakehouse duckdb path must be relative to the manifest` |
| DuckDB file absent | `lakehouse duckdb not found: export.duckdb` |
| Checksum mismatch | `lakehouse duckdb checksum mismatch: export.duckdb expected=... actual=...` |
| Relation or physical column absent | `lakehouse relation lakehouse.topic cannot be read with the mapped columns: ...` |
| Invalid row values | `lakehouse topics contain invalid rows: ...` |
| Dangling reference or duplicate key | `lakehouse observation references unknown indicator ...` |
| DuckDB extra not installed | `duckdb is not installed; install the lakehouse extra with `uv sync --extra lakehouse`` |

## Versioning

The major version changes only when a producer must change its manifest
incompatibly. Minor versions may add optional fields in a future revision of the
contract. The current parser rejects unknown fields on purpose (strict
validation for a proposed contract), so adding a field requires a coordinated
parser change and a new minor version. Once a real producer exists, a later
major version may relax unknown-field handling.
